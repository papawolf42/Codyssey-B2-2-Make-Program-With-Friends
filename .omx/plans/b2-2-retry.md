# B2-2 재시도 계획 인덱스

요청: 기존 4인 진행의 비효율을 줄이도록 방법론 재설계.
방식: plan direct. 산출물은 실행 설계 문서이며 GitHub 작업 실행은 포함하지 않는다.

계획의 본문과 변경 기준은 [4인 병렬 협업 실행안](../../docs/0015_b2-2-retry-workflow.md) 한 곳에서 관리한다.

사용자의 추가 요청에 따라 [담당자별 상세 실행서](../../docs/0016_b2-2-retry-step-by-step.md)에 56개 Step의 화면 조작·명령·기대 결과·오류 대응을 제공한다. 개인 작업은 병렬이고 두 충돌 쌍만 내부 순서를 맞춘다.

- 요구사항과 재사용 판단: 본문 1~2절. instruction.md 71~167행 및 evalutation.md를 기준으로 판정.
- 작업 배정과 실행 단계: 본문 3~7절. 기존 기록 확인 → 공통 준비 → 개인 작업/리뷰 → 두 쌍의 실습 → 증빙 통합.
- 위험과 대응: 기준 SHA 불일치·자동 병합(5절), 공개 이력 재작성·기록 손실(6절), 리뷰/통합 담당자 대기(4·7절).
- 검증 및 수용 기준: 본문 8절. 전원 개인 기준, 팀 전체 실습·문서 기준, 구두 설명을 각각 확인.
- 제한: 실제 원격 현재 상태와 팀 실습 실행 여부는 확인되지 않았으며 미래 완료로 주장하지 않는다.

문서 검토: 원문 요구사항 매핑, 역할/리뷰 배정, 단계 간 선행 조건, 로컬 링크와 문서 diff를 확인한다. 팀 실습 완료 판정은 본문 8절의 실제 증빙을 사용한다.
