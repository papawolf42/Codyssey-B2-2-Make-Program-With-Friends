| **Git 이력 상태** | 과거 실패 시도의 꼬인 브랜치·커밋이 뒤섞여 복잡함 | 교과서처럼 완벽한 다이아몬드 PR 머지 그래프 (`test/`와 동일) |

| **감점 리스크** | 과거 PR의 리뷰가 "LGTM" 수준이거나 충돌 증빙 누락 위험 | [evalutation.md](../evalutation.md)의 모든 평가 기준 100% 충족 |
| **필요한 사전 작업** | 이전 PR/이슈 전수 검사 및 부족분 감사(Audit) 표 작성 | 기존에 써둔 노트 텍스트만 복사해 둘 메모장 준비 |

## 🔍 3. 세부 분석

### 옵션 A. 기존 저장소 이어 쓰기 (Reuse & Delta)

* **저장소**: 기존 `nick19850906-debug/mission_02_02`
* **방식**: [0015 실행안](0015_b2-2-retry-workflow.md#2-시작-지점-이미-한-일을-확인한다)의 "이미 한 일 확인 표"를 운영 Issue에 올리고, 팀원별로 부족한 PR/리뷰만 골라서 작업.

#### 👍 장점
1. **작성했던 글 보존**: 이미 작성된 학습 노트 초안이 `main`에 있으므로 글을 다시 복사해 넣는 수고를 덜 수 있습니다.
2. **누적된 커밋 수**: 이미 14개 이상의 커밋/PR 기록이 존재하여 저장소가 풍성해 보입니다.

#### 👎 단점 및 리스크
1. **과거 이력의 부실 검증 리스크 (치명적)**:
   - 과제 핵심 조건인 **"특정 라인 근거 실질 리뷰 코멘트"**와 **"피드백을 받아 코드를 수정한 2차 커밋"**이 기존 PR 7개에 충실히 들어있는지 일일이 검수해야 합니다.
   - 만약 당시 리뷰가 단순 칭찬이나 확인에 그쳤다면, 어차피 추가 PR을 열어 다시 해야 합니다.
2. **충돌 2회 인정 여부의 불확실성**:
   - 기존에 시도했던 충돌 1건이 과제 평가 기준(동일 hunk 또는 이동/수정)을 엄밀히 만족하는지 증빙이 모호할 경우 감점 위험이 있습니다.
3. **커뮤니케이션 비용 폭증**:
   - "상교 님은 PR 2개 됐는데 양환 님은 리뷰 1개가 부족하니 이번 PR에 리뷰를 달고..." 처럼 팀원마다 해야 할 일이 달라져 혼선이 발생합니다.

### 옵션 B. 새 저장소 새로 생성 (Fresh Start) — 🏆 강력 추천!

* **저장소**: 조은익 님의 새 GitHub 저장소(또는 신규 Organization)
* **방식**: [0017 초간편 가이드](0017_b2-2-easy-guide.md)의 0단계부터 3단계까지 순서대로 진행.

#### 👍 장점
1. **가장 빠른 완료 (1시간 컷)**:
   - 4명이 디스코드나 음성 채널에 모여 0017 가이드의 명령어를 복붙하며 진행하면, **서로 묻고 따질 필요 없이 1시간 안에 전체 과정이 종료**됩니다.
   - 노트 내용은 이미 작성해 둔 파일에서 그대로 복사해 오면 되므로 작문 부담이 0입니다.
2. **예술적인 Git 커밋 그래프 완성**:
   - `test/` 폴더에서 검증했던 그 아름다운 그래프가 실제 팀 저장소의 `git log --graph --oneline --all`로 100% 동일하게 재현됩니다.
   - 평가 멘토가 열어보는 순간 **"브랜치 전략과 협업 흐름을 완벽히 이해하고 수행한 모범 팀"**이라는 인상을 줍니다.
3. **계산할 필요 없는 1:1 완벽 대칭**:
   - 시작점과 끝점이 명확하므로, 4명 전원이 정확하게 필수 조건(PR 2개 이상, 리뷰 2개, 피드백 반영 1회, 트러블슈팅 1개)을 빈틈없이 채웁니다.
4. **리뷰·충돌 증빙의 100% 합격 보장**:
   - 0017 가이드에 적힌 리뷰 대사와 충돌 2종(`review-request.md`, `sync-timing.md`)을 그대로 수행하므로 비자명 충돌 요건을 완벽하게 만족합니다.

#### 👎 단점
* 팀 저장소를 새로 파고 팀원 3명을 다시 초대해야 하는 약 3분의 사전 작업이 필요합니다.

## 🎯 4. 팀 상황별 최종 선택 가이드

### 상황 1. "오늘 1~2시간 모여서 깔끔하게 끝내고 싶다" ➔ **[옵션 B (새 저장소)]** 선택
* 가장 추천합니다. 과거에 꼬였던 기억은 잊고, 정돈된 [0017 가이드](0017_b2-2-easy-guide.md)를 내비게이션 삼아 처음부터 끝까지 속도감 있게 완주하는 것이 멘탈 건강과 학점 모두에 이롭습니다.

### 상황 2. "팀원들이 모일 시간이 아예 없고, 각자 10분씩만 투자해야 한다" ➔ **[옵션 A (기존 저장소)]** 선택
* 팀 회의가 불가능하다면 기존 저장소를 유지하고, [0015 실행안 2절](0015_b2-2-retry-workflow.md#2-시작-지점-이미-한-일을-확인한다)의 표를 만들어 각자 부족한 PR 개수만 핀포인트로 올립니다.

## 📝 5. 새 저장소로 진행할 때의 초간단 체크리스트 (1시간 로드맵)

새 저장소로 결정했다면 아래 5단계로 끝냅니다:

1. **저장소 생성 (5분)**: 조은익 님이 새 Public 저장소 생성 ➔ 팀원 3명 Collaborator 초대 ➔ `main` 브랜치 보호 설정 (PR 1명 승인 필수).
2. **0단계 공통 준비 (10분)**: 김상교 님이 준비 Issue #1 생성 ➔ `feature/retry-setup` 브랜치에서 가이드/템플릿/연습파일 커밋 ➔ PR #2 올리고 장양환 승인 후 머지.
3. **1단계 학습 노트 4종 동시 진행 (15분)**: 4명이 각자 Issue #3~#6 생성 ➔ 각자 브랜치에서 기존 노트 내용 복붙 ➔ PR 올리고 순환 리뷰 코멘트 ➔ 피드백 반영 2차 커밋 ➔ 머지!
4. **2단계 짝꿍 충돌 & 트러블슈팅 (20분)**:
   - 1조(상교+양환): amend / reset 실습 + `review-request.md` 충돌 해결 및 머지.
   - 2조(은익+건우): revert / stash 실습 + `sync-timing.md` 충돌 해결 및 머지.
5. **3단계 최종 제출 정리 (10분)**: 김상교 님이 `SUBMISSION.md` 링크 채우고 Git 로그 뽑아서 PR #11 최종 머지 ➔ **과제 완료!** 🏆
