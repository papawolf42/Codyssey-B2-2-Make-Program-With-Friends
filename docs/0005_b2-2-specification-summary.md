# B2-2 과제 핵심 명세 및 합격 체크리스트

> **미션명**: 친구 3~5명과 함께 프로그램 만드는 법 연습하기 (Python과 Git 심화)  
> **과제 코드**: B2-2 (`185007`) | **학습 시간**: 20시간 | **필수 여부**: 필수  
> **원문 참조**: [`instruction.md`](../instruction.md)

---

## 1. 과제 목표 및 성격

- **본질**: 코딩 실력 테스트가 아닌, **실무 Git/GitHub 팀 협업 워크플로우 시뮬레이션**
- **학습 핵심**: 브랜치 보호 규칙, GitHub Flow, Issue-PR 연동, 코드 리뷰, **의도적 충돌 해결(비자명 충돌 필수)**, Git 4대 트러블슈팅 체득

---

## 2. 저장소 및 환경 준비

- [ ] **팀 구성**: 3~5인 1팀 구성
- [ ] **저장소 형태**: **GitHub Organization 생성 권장** (대체: 개인 레포 + Collaborator 초대)
- [ ] **Branch Protection Rule 설정 (main 브랜치)**:
  - [ ] `main` 브랜치 직접 push 금지
  - [ ] PR(Pull Request)을 통한 병합만 허용
  - [ ] 최소 1명 이상의 승인(Approve) 필수
  - [ ] 관리자 우회 금지(Do not allow bypassing settings)

---

## 3. 브랜치 전략 (GitHub Flow)

- [ ] **브랜치 구조**:
  - `main`: 항상 배포 가능한 깨끗한 상태 유지
  - `feature/<이름>-<기능>`: 작업 단위별 분기 브랜치
- [ ] **전략 채택 이유 기록**: GitHub Flow를 선택한 이유를 3줄 이내로 `README.md` 또는 `docs/CONTRIBUTING.md`에 명시
- [ ] **컨벤션 정의**: 브랜치 및 커밋 메시지 규칙(`feat:`, `fix:`, `docs:` 등)을 `docs/CONTRIBUTING.md`에 문서화

---

## 4. 이슈 기반 작업 및 코드 리뷰

- [ ] **이슈 ↔ PR 연동**: 모든 작업은 GitHub Issue를 먼저 생성하고, PR 본문에 `Closes #이슈번호` 포함 (자동 닫힘 연동)
- [ ] **팀원별 PR 기여**: 팀원 1인당 최소 **2개 이상**의 PR 생성 및 병합
- [ ] **팀원별 코드 리뷰**:
  - [ ] 팀원 1인당 최소 **2건 이상**의 동료 PR 리뷰 작성 (단순 "LGTM" 금지, 코드/라인 근거 피드백 필수)
  - [ ] 최소 **1회 이상** 리뷰 코멘트를 반영하여 추가 커밋한 이력 증빙 (리뷰 반영 경험)

---

## 5. 충돌(Conflict) 실습 (★ 합격 핵심)

- [ ] **충돌 횟수**: 팀 전체 기준 **최소 2회 이상** 충돌 유발 및 해결 기록 필수
- [ ] **비자명 충돌(Non-trivial) 1회 이상 필수**:
  - **자명한 충돌 (1회)**: 두 브랜치가 동일 파일의 같은 줄을 동시 수정하거나, 같은 경로에 새 파일을 각각 생성(add/add)하여 발생
  - **비자명 충돌 (1회 이상)**: 한쪽 브랜치에서 **파일 이동/이름 변경(`git mv`)**을 하는 동안 다른 브랜치에서 해당 파일의 **내용을 수정(Modify)**하여 머지 시 `CONFLICT (rename/modify)` 유발 및 해결
- [ ] **충돌 문서화**: `docs/conflict-resolution.md`에 다음 6대 항목 기록
  1. 참여자 (해결자, 상대방)
  2. 발생 상황 (브랜치, 대상 파일, 원인)
  3. 충돌 마커 원문 (`<<<<<<< HEAD`, `=======`, `>>>>>>>`)
  4. 해결 과정 및 선택한 전략
  5. 최종 결과 (해결 커밋 링크, PR 링크)
  6. 배운 점

---

## 6. Git 4대 트러블슈팅 실습

팀원 전원이 최소 1개 이상 분담하여 실습하고 `docs/troubleshooting-log.md`에 기록:

- [ ] **`git commit --amend`**: 방금 커밋한 메시지 오타 또는 누락 파일 수정
- [ ] **`git reset`**: `soft`, `mixed`, `hard`의 차이를 이해하고 실수 커밋 취소 재현
- [ ] **`git revert`**: 이미 원격(main)에 push/merge된 커밋을 안전하게 취소하는 역커밋 생성
- [ ] **`git stash` & `stash pop`**: 작업 중 급한 브랜치 전환 시 임시 보관 및 복원
