# B2-2 평가문항 대조 감사와 이해도 확인 기준

작성일: 2026-09-29. 기준: [evalutation.md](../evalutation.md) 전체 22문항과 [instruction.md](../instruction.md).

**현재 자료만으로 전체 PASS를 판정할 수 없다.** 로컬 모의 협업의 상당 부분은 확인되지만, 잘못된 증빙 SHA와 기록 누락이 남아 있다. 실제 팀 권한·브랜치 보호·GitHub PR 증빙은 별도 확인이 필요하다. 항목 2~4는 사용자가 직접 설명하고 판단하는 능력을 묻기 때문에 문서의 존재나 퀴즈 점수만으로 충족했다고 단정하지 않는다.

## 1. 검토 범위와 판정 기준

- 본체 저장소: `private`, 검토 시작 HEAD `cae69b39c4d9fb19546f64e225a31e283eee816a`.
- 실습 저장소: `test/` 서브모듈, `main`, HEAD `15d1faae998d77aa8da39c503da58fb74f656495`.
- `test/`의 Git 디렉터리는 본체 `.git/modules/test`이다. 현재는 `git -C test ...`로 실제 실습 이력을 조회할 수 있다.
- 작성자를 바꿔 가며 작업하고 merge commit을 PR로 표현하는 방식은 사용자가 허용한 **모의 연습**이다. 이 방식을 잘못으로 판정하지 않는다.
- 현재 로컬 파일과 Git 객체를 검토했다. GitHub 권한·보호 설정·웹 PR 상태는 직접 조회하지 않았다. 원격 주소나 push된 이력이 있다는 사실만으로 해당 설정과 실제 팀 참여를 추론하지 않는다.
- 원본 실습 파일과 이력은 수정하지 않았다. 이 문서는 감사 결과이며 실습 완료 증빙을 대신하지 않는다.

| 표시 | 의미 |
| --- | --- |
| 충족 확인 | 해당 요구의 파일·커밋 등 현재 확인 가능한 물증이 있음 |
| 모의 범위 충족 | 허용된 로컬 역할 연습으로 확인됨. 실제 팀원 계정·GitHub 기능 수행까지 증명하지는 않음 |
| 부분 확인 | 유효한 기록이 있으나 오류·누락·검증 한계가 있음 |
| 미확인 | 현재 물증 또는 사용자의 직접 답변이 없어 판단할 수 없음 |
| 해당 없음 | 조건부 보너스를 수행했다는 근거가 없어 기본 필수 평가에서 제외 |

## 6. 이해도 확인 웹의 판정 원칙

학습 웹은 위 22개 문항을 원문 ID에 연결한다. 제출물 상태와 학습 결과는 별도로 표시해야 한다.

1. **구별하기:** 상황형 선택 문제로 명령·절차·증빙을 구분한다. 답 제출 후 정답 이유와 오답이 만드는 결과를 보여 준다.
2. **설명하기:** 항목 2~4에서 짧은 자유 답변을 작성한다. 사용자가 이유·순서·주의점을 직접 말하는 단계다.
3. **근거 대기:** 실제 실습의 SHA·파일·PR/Issue 위치를 찾아 연결한다. 개인별 참여 증빙은 지식 문제 정답으로 대체하지 않는다.
4. **재확인:** 틀린 주제를 다시 풀고, 예시 답안과 비교하되 본인의 근거와 예를 설명한다. 자동 점수는 학습 진척이며 공식 PASS가 아니다.

자유 답변의 글자 수나 특정 단어 포함 여부만으로 정답 판정을 하지 않는다. 필수 21문항과 조건부 보너스 1문항을 구분하고, 보너스 미수행을 필수 부족으로 계산하지 않는다.

## 7. 실제 제출 전에 남은 일

1. PR 대장의 존재하지 않는 반영 SHA 4개를 실제 SHA로 고친다.
2. `15d1faa`의 작업·검토 경위를 모의 대장에 연결하거나 실습 종료 후 문서 교정이라는 예외를 명시한다. 기존 이력을 지우거나 실제 없었던 PR을 과거 수행 사실처럼 만들지 않는다.
3. Issue 대장의 사전 등록·자동 종료 주장과 종합 revert 로그의 원격 상황 표현을 실제 모의 범위에 맞춘다.
4. Git 객체에 남지 않는 명령 전후 상태는 수행 당시 기록을 보존한다. 추가 연습을 한다면 새 연습과 새 증빙으로 구분한다.
5. 실제 팀 제출 단계에서 접근 권한·main 보호·실제 Issue/PR·승인·원격 공유 revert를 확인하고 SUBMISSION에 해당 링크를 연결한다.
6. 항목 2~4의 직접 답변과 상황 적용을 확인한다. 이해도 확인 웹은 이 마지막 확인을 돕는 학습 도구로 사용한다.

## 8. 확인에 사용한 로컬 조회

검토는 파일 읽기와 아래 종류의 조회로 수행했다. 원본 실습 이력에 checkout·reset·commit·push를 실행하지 않았다.

```bash
git submodule status test
git -C test status --short --branch
git -C test rev-parse --show-toplevel --git-dir HEAD
git -C test log --first-parent --format='%h %p %s'
git -C test show -s --format='%h %an %s' <증빙-SHA>
git -C test show 74ac7c8:src/practice/review-request.md
git -C test show ac641ec:src/practice/sync-timing.md
git -C test diff 20b886d^ c77b7e9 -- src/practice
```

이 감사는 위 기준 SHA의 스냅샷이다. 이후 실습이나 문서가 바뀌면 해당 항목만 다시 검토한다.
